# Plan: Module 2 – BYO Retrieval + Memory

**Complexity:** ⚠️ **Medium (upper end)** – DB + Storage + Realtime + ingestion pipeline + tool-calling chat loop + two frontend pages. Six sequential phases, each independently validatable. Backend (Phases 1-4) is fully pytest-verifiable before any UI exists. If context gets tight, split at Phase 4/5 into 2a (backend) and 2b (frontend + docs).

On approval: save this file as `.agent/plans/2.byo-retrieval-memory.md` (CLAUDE.md convention), then execute with `/build`.

## Context
Module 1 uses OpenAI Responses (managed threads + file_search). Module 2 replaces it with our own pipeline: upload (.txt/.md) → Supabase Storage → chunk → embed (local Ollama) → pgvector; a `search_documents` TOOL called by the model through Chat Completions; stateless history we store and send; Realtime ingestion status; SSE streaming. Out of scope: PDF/DOCX/HTML (M5), dedup (M3), metadata (M4), hybrid/rerank (M6), connectors.

## Decisions (confirmed with user)
- **Option A:** fully remove the Responses API (`services/openai_responses.py`, `threads.openai_last_response_id`, `messages.openai_response_id`). No dual support.
- **Local models via Ollama** (OpenAI-compatible at `http://localhost:11434/v1`): chat `gemma4:e4b` (has `tools` capability), embeddings `embeddinggemma` (768 dims, 2048-token context; verified `/v1/embeddings` returns 768-dim vectors). Migration uses `vector(768)`.
- **Ingestion auth:** FastAPI `BackgroundTasks` with the user's JWT (no service-role key; RLS stays the single source of truth).
- **Citations:** all retrieved chunks above threshold from the turn's searches, deduped.

## Assumed defaults (env-configurable; change if wrong)
`LLM_BASE_URL`, `LLM_API_KEY` (placeholder OK for Ollama), `LLM_MODEL=gemma4:e4b`; `EMBEDDING_BASE_URL`/`EMBEDDING_API_KEY` (fall back to LLM_*), `EMBEDDING_MODEL=embeddinggemma`, `EMBEDDING_DIM=768`, optional `EMBEDDING_QUERY_PREFIX` / `EMBEDDING_DOC_PREFIX` (empty default; EmbeddingGemma benefits from `task: search result | query: ` and `title: none | text: `); `CHUNK_SIZE=1000` chars (must stay well under 2048 tokens; validate at startup), `CHUNK_OVERLAP=200`, `EMBEDDING_BATCH_SIZE=64`, `RETRIEVAL_TOP_K=5`, `RETRIEVAL_MIN_SIMILARITY=0.25` (tune on real docs – Phase 3 manual step), `MAX_TOOL_ITERATIONS=3`, `HISTORY_MAX_MESSAGES=20`, `HISTORY_MAX_CHARS=24000`, `MAX_UPLOAD_BYTES=5000000`. Files: `.txt`/`.md`, UTF-8, ≤5 MB. `OPENAI_*` env vars removed (user updates their own `.env`; never read it).

## Key design
- **Upload path:** `POST /documents {filename,size_bytes}` validates and creates a `pending` row, returns `{id, storage_path="{user_id}/{id}"}` → browser uploads directly to private `documents` bucket via supabase-js → `POST /documents/{id}/ingest` returns 202 and runs a BackgroundTask. On upload failure the browser calls `DELETE /documents/{id}`. No `python-multipart` needed.
- **Storage from Python:** raw `httpx` (`services/storage.py`) with `apikey` + user JWT headers, to avoid supabase-py storage auth plumbing.
- **State machine:** `pending → processing → completed | failed` (`failed → processing` via retry). Ingest claims atomically (`update … where status in ('pending','failed') or (status='processing' and updated_at < now()-10min) returning *`; none → 409). Steps: download → decode `utf-8-sig` (strip `\x00`, fail on empty) → delete old chunks → chunk → embed in batches (assert dim) → insert chunks in batches of 100 → `completed`. Any exception: delete that doc's chunks, `failed` + truncated `error`. `match_chunks` only returns chunks of `completed` documents.
- **Chunking:** hand-written recursive splitter (`\n\n`, `\n`, `. `, ` `, hard split) with overlap; pure function.
- **Retrieval RPC:** `match_chunks(query_embedding vector(768), match_count, min_similarity)` – `security invoker` (RLS applies), cosine, joins documents `status='completed'`, HNSW `vector_cosine_ops` index.
- **Tool loop** (`services/agent.py`): Pydantic `SearchDocumentsArgs`; stream `delta.content` as SSE; accumulate `delta.tool_calls` by index (tolerate missing index / split args); execute tool, append `tool` message, loop up to `MAX_TOOL_ITERATIONS`, final iteration `tool_choice="none"`; invalid args → error tool message. Extra SSE event `tool` for a "Searching documents…" UI indicator.
- **History:** read last N messages (trimmed by chars, starting on a user turn) BEFORE persisting the new turn; keep persist-after-success (no orphan user message). Tool messages not persisted (later turns may re-search).
- **Citations:** `{document_id, filename, chunk_index, snippet(240), similarity}`, persisted in new `messages.citations jsonb default '[]'` and returned by `GET /threads/{id}/messages`.
- **Delete:** storage object first (404 tolerated, other error → 502 and keep row), then row (cascades chunks).
- **LangSmith:** one `wrap_openai` client factory; `@traceable` spans `embed_query`, `retrieve`, `execute_tool`, `ingest_document` (own root trace; metadata holds ids only, but the wrapped LLM spans contain prompt and chunk text – see privacy caveat above).
- **Provider connectivity:** `embeddings.py` and `agent.py` catch connection errors and raise a clear "Cannot reach model provider at <url>" error (ingestion stores it in `documents.error`; chat emits an SSE `error`). Test: fake client raising `APIConnectionError` → that message, no traceback leak.

## Where data lives and how you interact with it (local models ≠ local data)
**Storage – unchanged by the move to Ollama.** Ollama only runs inference (chat + embeddings); it stores no documents.
- **Original files:** private Supabase Storage bucket `documents`, path `{user_id}/{document_id}`.
- **Chunk text + 768-dim embeddings:** Postgres `chunks` table (pgvector). **Threads, messages, citations:** Postgres.
- The backend streams files from Storage over httpx and keeps no local copy. Backend and Ollama run on the same machine, so `localhost:11434` is reachable.
- **Privacy caveat:** your Supabase project is cloud-hosted (migrations are pasted into its SQL editor), so documents and chunks sit in the cloud even though the models are local. LangSmith tracing also uploads prompts and retrieved chunk text (the `wrap_openai` spans, not just metadata – this corrects the earlier "ids only" note, which applies to metadata only). For a no-egress setup: `LANGSMITH_TRACING=false`, and optionally a local Supabase stack (Supabase CLI + Docker, which you'd run yourself since `.claude/settings.json` denies `docker`). The schema and migration are identical; only `SUPABASE_URL`/keys change. Not part of this plan unless you ask.

**Interaction – through the web UI** (`scripts/start-services.sh`, then http://localhost:5173):
- **Documents page (`/ingestion`):** drag-and-drop `.txt`/`.md`, live status badges (pending → processing → completed/failed via Realtime), retry, delete.
- **Chat page (`/`):** ask a question → "Searching documents…" indicator → streamed answer → citation chips (filename, snippet, similarity; also shown when reloading a thread). Thread history in the sidebar.
- **API:** `curl -N -H "Authorization: Bearer <jwt>" -X POST localhost:8000/threads/{id}/chat -d '{"message":"..."}'` streams the SSE events (`tool`, `delta`, `done`, `error`).
- **Inspect/debug:** Supabase dashboard (documents/chunks rows, Storage objects) and LangSmith traces (`chat_turn`, `ingest_document`).
- **Operational requirement:** Ollama must be running with `gemma4:e4b` and `embeddinggemma` pulled. Embedding/chat connection failures map to a clear message ("Cannot reach model provider at <url>") – added to Phase 2/4 tasks below.

## Risks / ordering
- **Migrate first:** old backend breaks after the openai columns are dropped, new backend breaks without the tables. Stop → migrate → restart.
- **Dimension lock-in:** `vector(768)` ties to `embeddinggemma`; changing model needs a migration + re-ingest (runtime dim check fails early with a clear message).
- **EmbeddingGemma 2048-token context:** chunk size must stay well below; validated at startup.
- **Threshold is a guess (0.25):** tune on real docs.
- **gemma4:e4b tool calling:** reliability unverified; pytest uses fakes, so failure shows only in Phase 4 manual step – fallback is a tool-capable OpenRouter model via `LLM_BASE_URL`.
- **Ollama memory:** chat + embedding models swap in/out; first call after idle is slow.
- **JWT expiry in BackgroundTask:** negligible for ≤5 MB text; Retry covers restarts.
- **HNSW + RLS post-filtering** may reduce recall when a user owns a small share of chunks; acceptable at this scale.
- **supabase-py rpc vector param:** confirm a JSON array works; fall back to a `'[...]'` string.
- **Realtime auth:** if no events, call `supabase.realtime.setAuth()`.
- **Python 3.14 wheels:** no new compiled deps; still run a clean `pip install -r requirements.txt` once.
