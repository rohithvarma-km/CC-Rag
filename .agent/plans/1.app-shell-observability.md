# Plan: Module 1 – App Shell + Observability

**Complexity:** ⚠️ **Medium** – several moving parts (Supabase, FastAPI SSE, React, OpenAI Responses, LangSmith). Executed as 4 sequential phases, each validated before the next. On approval, save as `.agent/plans/1.app-shell-observability.md` (per CLAUDE.md).

## Context
Repo is docs-only (PRD, CLAUDE.md, PROGRESS.md); no frontend/backend/supabase/env files exist. Module 1 per PRD: **auth, chat UI, OpenAI Responses API (managed threads + file_search), LangSmith tracing**. Goal: a working chat app on managed RAG, with observability from day one. No custom ingestion/pgvector (Module 2). Module 2 will *replace* the Responses code (Option A), so keep it isolated in one service module and one table.

## Assumed defaults (change if wrong)
- Supabase: **cloud project** (user supplies URL/keys); migrations in `supabase/migrations/`.
- Auth: **email + password** via Supabase Auth.
- file_search: user supplies an existing OpenAI **vector store ID** in env (`OPENAI_VECTOR_STORE_ID`); no upload UI/code. Optional tiny `backend/scripts/seed_vector_store.py` to upload sample files.
- Model via env `OPENAI_MODEL`.

## Phase 1 – Foundations & DB
1. Scaffold `backend/` (python -m venv venv; fastapi, uvicorn, openai, langsmith, pydantic-settings, supabase, pyjwt/httpx, pytest) and `frontend/` (Vite react-ts, Tailwind, shadcn init). Add `.env.example` files, `.gitignore`.
2. Migration: `threads(id uuid pk, user_id uuid → auth.users, title, openai_last_response_id text, created_at, updated_at)`; `messages(id, thread_id, user_id, role, content, openai_response_id, created_at)`. **RLS enabled** on both, policies `user_id = auth.uid()` for select/insert/update/delete.
- **Validate:** `/health` returns 200; apply migration; with two test users, user A cannot select/insert user B's rows (SQL/REST check).

## Phase 2 – Auth
1. Frontend: Supabase client, Login/Sign-up page, session guard; unauthenticated → `/login`, authenticated → Chat (default view). Sign-out.
2. Backend `auth.py`: FastAPI dependency verifying the Supabase JWT (Bearer), returns user id; DB access uses the user's JWT so RLS applies.
- **Validate:** pytest: no/invalid token → 401, valid → 200 on `/me`; browser: sign up, sign in, refresh persists session, sign out redirects.

## Phase 3 – Chat with Responses API + SSE
1. `services/openai_responses.py`: `client.responses.create(model, input, previous_response_id=thread.openai_last_response_id, tools=[{"type":"file_search","vector_store_ids":[VS_ID]}], stream=True)`; yield text deltas (`response.output_text.delta`) and capture final response id from `response.completed`. Surface file citations if present.
2. Routers: `GET/POST /threads`, `GET /threads/{id}/messages`, `DELETE /threads/{id}`, `POST /threads/{id}/chat` → `StreamingResponse` (`text/event-stream`); persist user message first, assistant message + new `openai_last_response_id` on completion; auto-title from first message.
3. Frontend: thread sidebar (list/new/delete), message list, input, SSE consumption via `fetch` + ReadableStream (needs auth header, so not EventSource), incremental render, loading/error states.
- **Validate:** pytest with mocked OpenAI stream (events order, persistence, previous_response_id chaining); manual: second message in a thread shows memory ("what did I just ask?"); question answerable only from the vector store returns file_search-grounded answer.

## Phase 4 – LangSmith Observability
1. Env: `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT`. Wrap client with `langsmith.wrappers.wrap_openai`, and decorate the chat handler with `@traceable` (attach `user_id`/`thread_id` metadata, no secrets).
- **Validate:** send a chat; trace appears in LangSmith with inputs, streamed output, latency, token usage and file_search tool call.

Run `pytest` and `npm run build`/`tsc`.
